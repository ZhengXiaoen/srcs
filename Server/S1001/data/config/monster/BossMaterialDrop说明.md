# BOSS 普通材料整组掉落

参考提交 `8b5d8c9fef9904791d27889d9c47162fb6faddbd` 的 `Item.createItem` 和 `Item.createDropItem` 写法，将同类材料按数量创建并落地，减少逐件散落。

## 配置与规则

- `BossMaterialDropCfg.lua` 保存从 154 个原掉落模板迁移的 391 条记录，涉及 41 种可叠加且不通报的材料。
- `BossMaterialDrops` 沿用原记录的道具 ID、数量、倒数概率和绑定状态；重复记录仍分别抽取，成功数量按道具 ID 和绑定状态汇总。
- `propability=1` 必掉，`propability=0` 禁用，其他值表示几分之一。引擎优先使用正数 `count`，仅非正数时使用 `mincount/maxcount`。
- `BossMaterialDropMonsters` 按 `StdMonster.txt` 中原掉落模板的引用顺序配置，共覆盖 574 种怪物，其中 3 种普通怪与 BOSS 共用模板，也同步迁移以保留其奖励。
- `BossMaterialMaxStack` 与前后端 `StdItems` 的 `dup` 一致，超过单组上限时拆组。
- `MonsterFunction.lua` 在原一次性掉落检查通过后执行整组掉落；原模板中相应记录已删除，避免重复奖励。
- 带拾取保护或共用装备抽选组的 12 条材料记录保留原生处理，装备、活动条件及其余掉落不变。

后续新增或修改奖励时，应同步维护上述三个配置表与怪物模板引用，不要在原掉落模板和整组配置中重复配置同一份奖励。新增带特殊条件的记录应继续使用原生掉落，或先补充相应规则支持。

## 验证

- `tools/test_boss_material_drop.py` 提供 10 项 Lua 5.1 回归检查：迁移前后奖励、模板引用、数量汇总、绑定、叠加上限、一次性限制、玩家与宠物及战将击杀、失败释放、特殊规则及不通报行为。
- 原模板未迁移内容逐字节核对，保持不变。
- 完整 `MonsterFunction.lua` 与 `GlobalFunction.lua` 已使用服务器原生预处理器和当前服务器的 Lua 编译器隔离编译通过，未启动第二个服务器或修改运行中数据库。
- 已核对 41 种道具的前后端 ID 和叠加上限，独立资源包与 `zh-cn.dat` 副本一致；客户端现有掉落协议已支持数量显示，无需修改打包资源。
