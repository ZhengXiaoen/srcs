## 确认的失败路径

1. 原整理先 removeItem(false)，再 addItem 恢复原指针。AddUserItem 构造 ItemOPParam 时只复制 ID、数量、绑定、品质、强化、强化上限、转生和锋利；未复制物品的到期时间和道士强化。参数与已有物品的堆叠检查却比较这两个字段。因此即使原物品属性完全相同，重新加入仍可能分成两格。
   - 参数构造字节：`0x1402a756b`，REA `ev_9457c1ef6624df68e3c3339d2e18be3ce81de8b66a2a4297e75743d3165e092d`。
   - 参数堆叠检查：`0x1402a8c40`，REA `ev_d4e901e298f5128fd4b6aa123de413aecf9b78f1e5ecbaa9d988686bccec963b`。
2. GetItemRuneAttr 直接返回符文槽类型及原始 float 载荷。空槽（类型为 0）的载荷没有实际属性意义，但旧整理也比较它。若载荷是 NaN，两份相同物品也会被判断为不同，导致整种 ID 禁止合并。
   - 原生读取：`0x1403285b0`，REA `ev_f55b575bb820bebc3297476597a6f3691e806d70158c537fcd3850174fb24be4`。
   - Lua 桥按 float 转 double 返回：`0x14036e310`，REA `ev_4dc93e294f6b7005e361e4c4c3dfdee56db0401f9b3d70fce76be7bad5653dbb`。
3. 旧整理同 ID 任意一格属性不同就禁止所有格合并，连其他两格属性完全相同的物品也无法合并。

## 修复

- 整个背包先绑定，再按同 ID、同有效属性寻找目标格。
- 使用原生 setItemProperty(count) 增加目标数量、removeItem(true) 扣除源数量并删除空格，绕开重新加入参数不完整的路径。
- 每格使用配置堆叠上限（最高 9999）；满格留下余量。
- 写入目标失败不扣源；扣源未足额时将目标恢复为实际转移数量。
- 忽略空符文槽的无效数值，仍保护有效符文、附魂和其他可读属性。
- 使用完整 GUID 字符串重新查找，源格清空后不再访问已释放指针。
- 未修改原生程序、客户端资源或道具堆叠配置。

setItemProperty 的 Lua 桥确实返回 boolean：`0x14036dfe0`，REA `ev_475715c19c7e4f8ec82142cd05fe0ce6c98f25949e6c611e24b186a1b7ebdbf0`。
数量 setter 写入两个数量字节；成功后调用物品更新通知 `0x140288300`，REA `ev_9c005a2a66b8bf97f40d4c801808e1f11f251317392fd66cff81d5fc326a9a10`。
